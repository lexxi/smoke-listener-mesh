Remote-Benennung und eigenständiger Neustart erfordern v0.6.13 auf Gateway und Ziel. Discover zeigt bereits empfangene Mesh-Knoten; es ist keine aktive Funk-Suche. Namen bleiben über Neustarts im NVS gespeichert. Alarmfunktionen laufen unabhängig von dieser Seite.

1 · Discover

Erkannte Knoten aus den empfangenen Mesh-Meldungen. Funkstatus kann danach gezielt abgefragt werden.

2 · Ausgewählten Knoten verwalten

Neustart ist ein eigener Befehl, unabhängig von OTA-Aktivierung. Nicht während eines Firmwareupdates ausführen.

3 · Knoten registrieren

Aus Discover auswählen, Stammdaten speichern und optional für signierte OTA-Updates freigeben. Ein neuer Knoten wird nicht allein durch Funkempfang automatisch freigegeben.

Bei neuen Knoten ist NAME SET vorausgewählt, bei bestehenden Knoten nicht (damit Standortänderungen keine Fernumbenennung auslösen). Erst werden die Stammdaten gespeichert, anschließend wird NAME SET ausgeführt. Ein Fehler beim Funkbefehl wird getrennt angezeigt. Bereits signierte ZIP-Pakete enthalten kein Manifest für neu registrierte Geräte.

4 · USB-Gateways verwalten

Der dedizierte COM16-Logger ist geschützt. Weitere USB-Gateways lassen sich hinzufügen oder entfernen. Änderungen werden nach Webapp-Neustart aktiv; Mesh-Knoten und OTA-Ziele bleiben bestehen.
